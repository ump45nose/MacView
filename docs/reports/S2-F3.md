# S2-F3 设置、会话恢复、状态显示与调试接口

2026-11-03，MacPro，分支 `feat/s2-p0`。

## 做了什么

- `App/Settings/`：SwiftUI 设置窗口，全应用一个，四页（浏览、显示、缓存、路径规则）。改动立即反映在界面上，去抖 150 ms 写入；外部改文件后窗口更新。继承来源用 `PathRule.matching` 和 `applying` 逐层算出。
- Core：`PathRule.matching`（`resolve` 共用）；`FileImagePipeline.setMaxDecodeLongSide`；`ReaderSession` 的全局设置改为被观察，只改解码上限时查看器也会重新请求。
- `App/Shell/SessionStore.swift`：`session.json`，见架构 §3.8。按窗口多存一个瀑布流尺寸。
- `VolumeStatusView`、按文件显示的 `FileErrorBanner`、`ErrorText` 的 `MediaError` 文案。
- `App/Debug/DebugSocket.swift`：协议见架构 §3.8。
- 修掉两个界面问题：状态栏的 Mock 图标在真实服务下也显示；查看器提示的按钮没有居中。
- 自检：`-MVSettingsSelfTest`、`-MVSessionSelfTest <阶段>`；`-MVAppearance` 选外观。

## 证据

- `-MVSettingsSelfTest`：`SELFTEST OK`（C2.14–C2.16，解码上限用 3000×2000 的图，请求从 1397 变成 1024）。
- `-MVSessionSelfTest`：`write` 后 `kill -9` 退出码 137，`verify`、`verify` 加启动 URL、`missing`、`corrupt`、`settings`（中、英）、`volume`（Mock）都是 `SELFTEST OK`。
- 调试接口：`nc -U` 依次发 `open`、`perform`、`state`、`resize`、`scroll`、`quit`，结果与状态一致，`quit` 后退出码 0；错误命令和非 JSON 都返回 `ok: false`。
- Release 构建：`nm` 里没有 `DebugSocket`、`DebugCommands`、`SyntheticScroll`，`strings` 里没有 `MVDebugSocket`。

## 与任务文档的偏差

- 缓存页没有用量和“清除…”：Core 没有接口。
- 路径规则的覆盖项不含 `fixedScale` 和 `sharpen`。
- 同一本书开在两个标签时共用一份书记忆。
- 全屏不进会话。
- `session.json` 解析失败时不覆盖坏文件，直到修好或关掉错误条（避免空窗口马上把它写掉）。
- 配置错误条的标题统一成“有错误，继续使用可用的配置”。缺全局字段不算解析失败。
