# G5 全量验收：S5 扩展

日期：2026-11-25。冻结提交：`88793deaac161f121a47d95d8e388bdee7331d99`。安装版产品提交：`8533aaf`（至冻结提交只有路线图记录变更）。

**结论：G5 未通过，暂不放行。** 全量 Core 测试及 S5 Debug 自检无失败，但示例插件「页面笔记」的正常文字输入在安装版崩溃两次、冻结 Debug 崩溃一次；安装版底部停靠面板停用再启用后正常恢复，重启 App 后却不再显示。另在真实本机 WebDAV 停服恢复后的重试中，书架恢复而阅读主区仍显示旧错误。自动化通过不能抵消上述实际观察。尚未达到条件的子动作列在手动验收清单中。

## 做了什么

- 按 [路线图 S5](../plans/roadmap.md#s5-p1-扩展关口-g5) 和 [需求](../plans/requirements.md) 验收脚本与外部命令、插件宿主、HTML/JS 面板及 Core 诊断信息本地化。原 S5-T1、T2 需求 worktree 已删除，从 Claude 项目历史会话恢复 T1 六条、T2 八条场景，加上本轮用户提供的 F1 八条，共 22 条正式场景；另对路线图要求的安装版 F1 八条、网络卷、菜单定制、Safari 和原生标签栏进行走查。原始来源和逐项判据见[场景矩阵](bench/g5-20261125/scenario-inventory.md)。
- 由 `gpt-6-luna high` 检索原始需求，`gpt-6.2-astra xhigh` 分别承担自动化及真实界面验收；主控按证据审核和裁定，不修改产品源码。
- 干净冻结源码构建 Debug/Release，排除主工作区原有未跟踪资源目录，不替换安装版。Core 及 Debug 以独立目录运行，安装版不使用 `-MV…` 参数。安装版实测前完整备份真实支持目录，利用系统的独立 home 运行测试数据，结束后逐项核对原目录。
- 在 MacPro 本机实际运行 App，使用已获授权的 GUI 工具操作真实菜单、键鼠事件路径，并核对窗口截图、辅助功能内容、实际进程及服务输出。WebDAV/HTTP 替身仅在本机工作区运行；未改动 NAS、网络配置、系统授权或现有挂载。外网两项按本轮明确约定留给手动环境。

### 首要失败：普通页面笔记输入导致整个 App 退出

安装版与冻结 Debug 都从示例插件的正常文字输入路径触发，不涉及异常插件或权限绕过。实际先正常打开书、启用并打开「页面笔记」、确认面板显示页名和尺寸，然后点击笔记框输入普通文本。两次安装版和一次 Debug 均退出，有系统 `.ips` 报告。第二次安装版及 Debug 仅按一个字母 `a` 即触发。

| 时间（本机） | 构建 | PID | 结果 |
|---|---|---:|---|
| 15:54:13 | 安装版 Release `8533aaf` | 3593 | SIGABRT |
| 16:02:38 | 安装版 Release `8533aaf` | 10191 | SIGABRT |
| 16:18:28 | 冻结 Debug `88793de` | 19112 | SIGABRT |

三个报告均指向主线程 `NSUndoManager _prepareEventGrouping`、`WebKit::WebViewImpl::registerEditCommand`；安装版 UUID `DF480220-44A8-3365-9E5E-A600229943C1`，Debug UUID `B9982535-FA91-377F-A6B0-2396EEAE3BEB`，与对应二进制核对一致。仅凭栈不裁定根因。实际用键盘写入这项本应是 F1-S2 的主路径，因崩溃没有真实保存的笔记可供重启验证。即使 C2.11 四轮全过，本条仍明确失败。

### 另一个待定位现象：WebDAV 恢复后阅读主区旧错误未清除

安装版实际打开本机 WebDAV 来源，目录与图像读取成功。停服后出现连接失败和重试按钮，App 仍能操作。恢复本机服务后在错误页点击「重试」，16:24:40 服务端返回两个 PROPFIND 207，书架显示三本书，但约 0.9 秒后的同一阅读窗口仍显示原连接错误及重试按钮。主控核对窗口截图，确认书架确有三本而主区仍是错误页。后来从书签另行打开 Book-B 可正常读页。该次未确认错误页自行恢复原阅读内容，不能将重新打开当作同一次重试成功，也不能根据 0.9 秒的观测断定一定不会稍后恢复。保留 T2-S3 为部分完成、需复验。
