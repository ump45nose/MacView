# S1-T8 组合根与集成测试

## 实现

`CoreServices.make` 连接文件系统、压缩包、I/O 调度、L0–L3 缓存、图像管线、设置、书架和阅读加载器。`keybindings.json` 使用 `JSONDocumentStore<KeyBindingsFile>`；Core 创建空 `CommandRegistry`，命令处理器由 App 登记。组合根弱引用会话，统一订阅内存压力和全局预算变化：warning/critical 将 L0/L1 收缩到预算的 50%/25%，取消 background 预取；预算变化更新 L0–L3，L3 开关下次启动生效。

退出依次执行会话 `flush`、`FileImagePipeline.shutdown`、`FileSettingsStore.flush`、`CacheIndex.flush`、`IOScheduler.shutdown`。900 ms watchdog 取消后续落盘，同步调用 package 级 `beginShutdown` 永久关闭管线工作入口，并弃用辅助进程，以满足 1 秒总期限。管线将 `ContentWork`、`SharedWork` 和独立衍生件的真实任务跟踪到结束；已交付的 tiled/animated source 及网络视频 byte source 也受生命周期边界约束。

三项修复已实现并通过独立复验：

- **C4.2**：`ExtractStore` 将旧 `extract` 改名为同级 UUID 回收目录并新建空目录；后台只扫描父目录一层以识别和删除本应用的回收目录，解出预算从空开始。
- **C4.4**：管线停止接收新工作，取消并排空在途读取、解码和缓存写入，包括独立衍生件任务，再由组合根继续落盘与退出。
- **C4.12**：`TarIndex` 按字节解析 PAX 记录，只将使用的 `path`、`size`、`mtime` 值解码，允许其他值含非 UTF-8 字节。

`CacheIndex`、`FileSettingsStore` 现有公开接口提供 `flush`，数据库句柄随服务释放。未新增依赖；沿用 GRDB.swift 7.11.1（MIT）及既有系统框架。
