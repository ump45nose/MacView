# S1-T8 组合根与集成测试

## 实现

- `CoreServices.make` 用传入的 support/cache/browseBounds/helperExecutable 连接真实的文件系统、压缩包、I/O 调度、L0–L3、元数据和目录索引、图像管线、设置、书架和阅读加载器。
- `keybindings.json` 使用版本 1 的 `JSONDocumentStore<KeyBindingsFile>`；Mock 保留原构造入口。Core 创建空 `CommandRegistry`，命令处理器归 App。
- `makeSession` 只弱引用会话。退出依次执行会话 `flush`、`FileSettingsStore.flush`、`CacheIndex.flush`、`IOScheduler.shutdown`；独立的 900 ms 期限在卡住时取消后续落盘步骤并弃用辅助进程，不等待阻塞 I/O。
- 内存压力只在组合根订阅：warning 把 L0/L1 现有内容收缩到预算 50%，critical 收缩到 25%，两者都只取消 background 预取。全局设置变更更新 L0–L3 预算，L3 开关在下次启动生效。

## 契约问题与偏差

- **C4.2 的“不扫描缓存目录”未通过。** 现有 `ArchiveProvider.init` 调用 `ExtractStore.init`，后者同步枚举并清空整个 extract 目录。W4.1 的明列边界不包含 MVArchive，主控决定本轮保留直接组装、据实交回设计，不用延迟包装或新目录绕开。建议后续在批准的 MVArchive 范围内将旧解出文件清理移到后台。
- **立即 shutdown 后重建存在竞争。** 复测时 `DiskCache.init` 同步删除 `browse/tmp` 失败（Cocoa 513，底层 EPERM）。会话的 `.book` 预取即使被 `cancelAll` 取消，`FileImagePipeline.bundle` 创建的独立 derivatives Task 仍可能在退出 flush 后写入 L2/L3，与新实例清理共用临时目录竞争。首次通过不能证明稳定退出；不能用 sleep、预先生成全部衍生件或禁用预取掩盖。管线退出/drain 或磁盘缓存多实例 staging 的设计需要在批准范围内补齐。
- **macOS tar 的 PAX 扩展元数据兼容性。** 最初用 `/usr/bin/tar` 默认格式打包本次图片副本时，tar 写入 `LIBARCHIVE.xattr.com.apple.provenance` 和 `SCHILY.xattr.com.apple.provenance`；后一值含非 UTF-8 字节，现有 `TarIndex.pax` 将整个键值解码成 UTF-8 后报“无效的 pax 键值”。规定的仓库标准 tar.gz 夹具副本可正常打开、探测和翻页。本轮不修改边界外 MVArchive 解析器。
- `CacheIndex`、`FileSettingsStore` 现有公开接口只有 `flush`，没有显式 close；本实现按阶段 4 确定的退出顺序完成落盘，数据库句柄随服务释放。未增加公共关闭接口。
- 未新增依赖；沿用 GRDB.swift 7.11.1（MIT）及既有系统框架。

## 未决项

extract 启动同步扫描、退出后重建的缓存竞争、macOS tar PAX 扩展元数据兼容性需要设计侧处理。当前 W4.1 不判完成。

推荐的最小修复范围：

1. `MVArchive/ExtractStore.swift` 与其测试：把旧解出文件清理从同步构造移到后台，确保 `make` 不枚举既有缓存。
2. `MVArchive/TarIndex.swift` 的 PAX 解析与其测试：先按声明字节长度分隔键值；忽略不消费的扩展属性时不要求其值是 UTF-8，保留实际使用的路径、尺寸、时间字段校验。
3. `MVPipeline/FileImagePipeline.swift`（必要时含 `SharedWork.swift`）、`MVServices` 退出连接及规定的重建用例：共享衍生件应随最后一个消费者取消而停止提交新写入，组合根在现有总期限内等待写入停止后再 flush 索引。仅让 DiskCache 为每个实例使用独立 staging 可减少目录竞争，不能单独证明退出后不再写入，因此需先明确管线生命周期契约。

重建竞争的最小触发步骤：打开 12 页真实 ZIP，翻到第十页，立即 `shutdown`，随即使用相同 support/cache 配置再次 `make`。错误发生在 `<work>/services-tests/<UUID>/cache/browse/tmp` 的同步删除阶段；调用链为 `ReaderSession.prefetch → FileImagePipeline.bundle → derivatives Task → DiskCache.store`，并发于新实例 `CoreServices.make → DiskCache.init → removeItem(tmp)`。
