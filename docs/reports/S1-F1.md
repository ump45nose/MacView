# S1-F1 App 外壳：报告

只记录验收证据、与任务文档的偏差和未决问题。实现见 `App/Shell/`、`App/Input/`、`App/Reader/`、`App/Resources/Localizable.xcstrings`。

## 验收证据

自检入口（Debug 构建）：`-MVSelfTest YES -MVSelfTestOutput <目录>`，见 `App/Debug/SelfTest.swift`。它在 Mock 上打开书，合成按键（CGEvent 转 NSEvent）后检查会话状态，把菜单清单写成 `menu.txt`，把窗口图层树渲染成 PNG，退出码为失败数。

```sh
make build && make test
APP=build/DerivedData/Build/Products/Debug/MacView.app
open -n -W --stdout out/zh.log -a $APP --args -MVSelfTest YES -MVSelfTestOutput out/zh
open -n -W --stdout out/en.log -a $APP --args -MVSelfTest YES -MVSelfTestOutput out/en -AppleLanguages "(en)"
```

测试时屏幕处于锁定状态，App 无法激活（没有 key window）。自检检测到这种情况时按 NSApplication 的顺序手动分派按键：窗口的 `performKeyEquivalent` → 菜单栏的 `performKeyEquivalent` → 窗口的 `sendEvent`。另外两项因文本输入上下文只对 key window 生效而跳过，自检输出为 SKIP：“字母进入了文本框”和“⌘W 关闭标签页”。在页码输入框里，Esc 与回车改为直接发送对应的编辑命令。App 处于前台时，自检走 `NSApp.sendEvent`。

## 与任务文档的偏差

- 服务一律用 `CoreServices.makeMock`，状态栏右侧标明“Mock 服务”。`CoreServices.make` 尚不存在（S1-T8），所以 `-MVMockServices` 开关和 `make` 失败时的错误窗口只留了入口：`AppDelegate.makeServices()` 抛错时弹出错误并退出。这一路径目前没有失败来源，未实测。
- `keybindings.json` 由 MVServices 管理（S1-T8），Mock 没有这份文档，所以生效绑定是 `KeyBinding.effective(defaults:user: [])`。解析失败的提示条随 S1-T8 接入。
- 翻页、跳页、切书的处理器由 App 登记，作用于对应窗口的 ReaderSession。S1-T8 如果在 Core 侧登记同名命令，需要约定由哪一侧登记（见未决问题）。
- 切书的排序：书架面板（S2-F2）之前没有书架排序，按名称升序。
- 工具栏只有上一本、下一本两个按钮，加上窗口标题（书名）和副标题（路径）。设计稿上的其他工具栏项没有加，因为它们的命令还没有处理器，或者属于后续任务：停靠区开关属于 S1-F2，浏览方式、排序和缩略图尺寸属于 S2。
- 新增 App 侧命令 `window.close`（⌘W），放在“文件”菜单末尾。
- 增加系统“编辑”菜单，否则文本框没有剪贴板与撤销命令。
- “跳到指定页…”做成状态栏内的页码输入框，不另开弹出层。

## 未决问题

1. **菜单快捷键的显示方式**：非 global 作用域的快捷键只在菜单打开时（`menuWillOpen`）写到菜单项上，菜单关闭后清除。原因如下：
   - 菜单项一直带着 →、⌘G 这类快捷键时，AppKit 会在按键到达响应链之前就拿它们匹配，菜单项不可用时还会吞掉按键。
   - 实测发现，`menuHasKeyEquivalent` 代理返回 false 之后，AppKit 仍会做第二轮匹配；NSMenu 子类重写的 `performKeyEquivalent` 也不会被菜单栏调用。
   - `menuNeedsUpdate` 在菜单栏的例行更新中也会被调用，不能用来写快捷键。

   需要用户打开菜单目测一次，确认快捷键显示完整（步骤见下）。
2. **textInput 作用域与 global 绑定**：global 作用域的快捷键是真正的菜单快捷键，焦点在文本框里或没有窗口时也可用。这符合 macOS 惯例，但 BindingResolver 的“textInput 不回退 global”只在 InputRouter 这一路成立。如果要求文本框里连 ⌘O 都不响应，需要改由设计侧决定。
3. **命令处理器的归属**：S1-T8 的范围写有“CommandRegistry（登记 Core 侧的默认命令清单）”。如果 Core 也登记翻页、切书，后登记的会覆盖先登记的。需要在 S1-T8 前约定：会话类命令由 App 登记（按 `CommandContext.session` 找窗口），还是由 Core 维护会话表。
4. 窗口关闭时，App 调用 `pipeline.cancelAll(session:)` 结束该会话的请求。ReaderSession 没有关闭接口；如果 S1-T6 之后会话自己持有预取，可以改由会话负责。

## 需要用户动手的验收

屏幕解锁后进行：

1. 运行 `make run`，依次打开“文件”“显示”“翻页”“书”“窗口”菜单，确认各项右侧显示快捷键（→、⌥→、Home、End、⌘G、⌥↓、Tab 等），没有截断或错位。
2. 用 `open -a <MacView.app> --args -AppleLanguages "(en)"` 启动，确认菜单和窗口文字为英文。
3. 用真实键盘重跑一次自检，确认没有 SKIP：`open -n -W --stdout /tmp/mv.log -a <MacView.app> --args -MVSelfTest YES`，然后 `grep -E "PASS|FAIL|SKIP" /tmp/mv.log`。运行期间不要切换到其他 App。
4. 从 Finder 把一个文件夹拖进窗口、拖到 Dock 图标，再用 ⌘O 选一个 zip。Mock 下应显示“只能打开 /Volumes/Mock 下的模拟目录”的错误表单；接入真实服务之后，应能打开。
5. 按 ⌃⌘F 进入全屏、再退出；点击标签栏的“+”新建标签页。
