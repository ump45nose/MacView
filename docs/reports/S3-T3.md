# S3-T3 / S3-T4 阶段 1：搜索索引、评分标签读写与变更链（Core）报告

记录日期：2026-11-19，分支 `feat/s3-search`（基于 `8f784a3`），范围 `.spec/stage-1.md`。本报告覆盖 S3-T3（搜索索引与 EXIF 详情）与 S3-T4（评分与标签的 XMP 读写及变更链）的阶段 1 Core 交付。

## 做了什么

- **MVMetadata（新模块）与 MediaProbe**：新增 `XMPFields`、`MetadataWritability`、`MetadataError`、`ImageDetails`、`MetadataFormat`、`XMPReader`、`XMPWriter`。支持按文件头识别 JPEG/TIFF/HEIC 可写性、从前 64 KB 读取 `xmp:Rating`（回退 `MicrosoftPhoto:Rating` 映射 1/25/50/75/99→1–5，0→nil）与 `dc:subject`、提取 EXIF/GPS 详情；内存改写 XMP 时使用 `kCGImageDestinationMergeMetadata` 保留原有元数据，并逐字节校验 JPEG 扫描段（SOS–EOI）或 TIFF/HEIC 首帧像素。`ImageMetadata` 新增 `rating`、`tags`，`FileChange` 新增 `.rewritten(Entry, previous: ContentIdentity, metadata: ImageMetadata)`，`MediaProbe.image` 同步带出评分与标签。
- **MVCache 搜索表与 SearchCatalog**：`index.sqlite` 新增迁移，建 `search_entries` 表（NFKC + 小写文件名、`Location.prefixKey` 索引与 `cacheKey` 索引）、为 `metadata` 增加 `rating` 列并新增 `metadata_tags(key, tag)` 表。`DirectoryCache.update` / `apply` 在同一事务中同步维护搜索行（含目录删除与移动的按前缀级联、`.rewritten` 替换）。实现 `SearchCatalog`（多词 AND、NFKC、通配符转义、scope 前缀隔离、评分/多标签/类型筛选、`tagSuggestions` 与 `indexedCount`）。
- **缓存改挂与元数据迁移**：新增 `DiskCache.rekey(prefix:to:)`、`MetadataIndex.move(_:)` / `remove(for:)`，以及 `ImagePipeline.carryOver(from:to:)`（`FileImagePipeline` 改挂 L2/L3 磁盘缓存并清理旧内存条目，避免改写元数据后重复解码）。
- **MVFileOps 写入与 MVIO 描述符释放**：新增 `FileOperation.setMetadata([Location], XMPFields)` 与 `FileOpsError.metadataUnsupported(String)`。单文件采用无缓存整读 → `XMPWriter.write` → 同目录 `.<名>.mvtmp-<uuid>` 写入 → 无缓存读回 SHA-256 校验 → 覆盖 `rename` 的原子流程，失败清理临时文件并保留原文件，`inverse` 为各文件原值组成的 `.sequence`。`MVIO/FileOperations.swift` 的 `FileReader.withInvalidatedCache` 在覆盖 `rename` 前同时释放目标路径缓存的读描述符（本机与辅助进程共用），防止 NFS 留下 `.nfs.*`。
- **MVCommands**：新增 `rating.set.0–5`（⌥0–⌥5）、`metadata.tags.edit`（⌥T）、`search.focus`（⌘F）、`search.indexFolder`、`panel.info.toggle`（⌥⌘I），接入 `CoreCommands.all` 与 `defaultMenu`。
- **MVServices 与 MVReading**：组合根文件变更链在目录缓存更新前后处理 `.moved`（含目录后代）的 `MetadataIndex.move`，以及 `.rewritten` 的元数据存储/删旧键与 `pipeline.carryOver`；`ReaderSession.applyFileChanges` 对 `.rewritten` 原位更新页 `identity` 与 `metadata`，不重载、不清显示。新增 `CoreServices.metadataDetails(for:)`（经 `SourceRegistry` 增量读头，支持压缩包内条目）。
- **MVSearch（新模块）与接线**：新增 `IndexProgress` 与 `FolderIndexer`（第一步递归枚举写入 `DirectoryCache`，跳过 `._*` 与回收目录、不展开压缩包；第二步按低优先级增量探测未缓存或已变更图片的元数据；取消即停、同卷串行排队、卷降级报错保留已完成部分）。`CoreServices.make` 与 `CoreServices.makeMock` 均接入真实 `SearchCatalog` 与 `FolderIndexer`。
- **mvbench**：新增 `search seed` 与 `search query` 子命令用于 10 万项检索基准。

### NFS 实测（C1.10、C1.16）

- **C1.10（NFS 大图元数据写入）**：在已挂载 NFS 测试目录 `~/MacViewBench/fileops-a` 对 47 MB（49,276,048 B）JPEG 先经辅助进程读取以缓存只读描述符，再写入 5 星与标签；耗时 **9.597 s**，扫描段/像素与读回校验通过，目录内无 `.mvtmp-*` 与 `.nfs.*` 残留。
- **C1.16（NFS 两步索引）**：在 `~/MacViewBench/fileops-a` 下对 300 个小 JPEG 运行 `FolderIndexer` 两步索引：`listing` **109.8 ms**，`probing` **4341.5 ms**，总计 **4451.3 ms**，`failures = 0`。

## 与任务文档的偏差

1. **`zoomDevicePixel` 默认快捷键调整**：从 `⌥1` 调整为 `⌥⇧1`，以消除与新增命令 `rating.set.1`（`⌥1`）在同作用域下的绑定冲突（保证 C1.19 `BindingResolver.conflicts` 为空）。
2. **覆盖 `rename` 释放目标描述符的位置**：改动落在 `Packages/MacViewKit/Sources/MVIO/FileOperations.swift` 的 `FileReader.withInvalidatedCache`（而非仅改 `FileSystemProvider.swift`），使本机与网络卷辅助进程共用同一套失效路径。
3. **App 侧穷举 switch 最小补齐**：除 `.spec/stage-1.md` 列出的 `FileChange.rewritten` 三处外，因新增 `FileOpsError.metadataUnsupported` 与 `FileOperation.setMetadata`，在 `App/Shell/ErrorText.swift` 与 `App/FileOps/FileOperationController.swift` 补齐了最小穷举 `switch` 分支以保持 App 目标编译。
