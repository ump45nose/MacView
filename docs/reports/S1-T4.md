# S1-T4 MVCache 实现报告

状态：已完成。W1.6 独立验收通过，1 万项目录及元数据的查询和 60 图读取均达到 C1.3 门限。

## 实现

- L0/L1：锁保护的字节成本 LRU，命中和单项移除为 O(1)，收缩按淘汰项数处理；运行时调整预算，内存压力按预算的 50% / 25% 收缩，预算本身保留。系统压力订阅由 MVServices 负责。
- L2/L3：共用一个 GRDB `DatabasePool` / WAL。专用串行文件队列协调临时写入、同步、原子改名、索引提交和淘汰；读取先批量查询索引，在有界文件队列上最多 16 并发读文件。缩略图和浏览图独立预算、独立索引命名空间。
- 命中访问时间先留在内存，1 秒或 256 个不同键触发批量写回；显式 `flush()` 和淘汰前也会写回。失败批次保留到下一次重试。
- 淘汰先提交索引删除再删文件，避免崩溃留下指向缺失文件的索引。启动只清空本层 `tmp/`，不扫描缓存分目录。每次实际淘汰顺带轮询一个哈希分目录，清理早于当前缓存进程启动的无索引普通文件。
- 元数据使用 MVFoundation 的 `ImageMetadata`，各字段按列存入 SQLite，通过容器索引一次范围查询，也支持按键子集查询和覆盖；旧版缓存 schema 直接重建，不保留 JSON 兼容路径，查询结果不做内存缓存。
- 目录缓存以单一带版本头的紧凑二进制格式保留完整 `Entry` 与目录修改时间，整份读取和解码；原子更新并返回按位置/内容身份计算的增删改差异。既有目录差异用例保留网络根、多层位置、非空创建时间、归档关联值、校验值和独立显示名的完整往返断言，没有新增测试函数。
- `mvtest-writer cache <目录>` 持续写入可逐字节核验的条目，供测试 SIGKILL；`mvbench cache` 预置 1 万个独立的有效合成 JPEG 缩略图，并实际重开 SQLite 查询、解码完整目录与 `ImageMetadata`，单独计时 60 图并发文件读取。
