## 与 §4 的差异

### 签名变更

| # | 位置 | 变更 | 原因 |
|---|---|---|---|
| 1 | `ResampleFilter` | 从 MVMedia 移到 MVFoundation | `BookSettings.resample` 要用它，而 MVSettings 只依赖 MVFoundation（§2）。 |
| 2 | `ReaderSession.openNeighborBook` | 增加参数 `sort: SortSpec` | 相邻书按书架的顺序，而书设置里的 `sort` 是书内页面的顺序。需求规定每个面板单独设置排序，所以由前端传入书架面板当前的排序。 |
| 3 | `CoreServices` | 增加公开的 `init(sources:pipeline:settings:commands:bookshelf:loader:)`，并私有持有 `BookLoader` | `makeSession()` 要用 BookLoader 创建会话。Mock 和 S1-T8 的 `make(configuration:)` 都经它组装。前端不直接用 BookLoader，所以不公开。 |

### 补全的定义

§4 只给出名字、或者没写明的部分：

- `CacheBudgets`：
  - 字段：`rawBytes`、`decodedBytes`、`thumbnailBytes`、`browseBytes`、`browseCacheEnabled`。
  - 默认值与 §3.4 一致：512 MiB、min(2 GiB, 物理内存的 10%)、10 GiB、50 GiB、开启。
- `PrefetchRanges` 的字段与默认值：

  | 字段 | 默认值 |
  |---|---|
  | `viewerDecodeFrames` | 2 |
  | `viewerReadAheadPages` | 5 |
  | `galleryMarginScreens` | 1 |
  | `currentBookPages` | true |
  | `neighborBooks` | 2 |
  | `shelfCovers` | true |

- `ResolvedBookSettings`：
  - `applying(_:)`：`BookSettings` 中有值的字段覆盖当前值。
  - `.default`：分页、单页、从左到右、首页单页、宽页单独成帧、按名称升序且文件夹在前、不递归（深度 1）、适合窗口、不放大、固定倍率 1、翻页不保持缩放、Lanczos、不锐化。
- `GlobalSettings.default`：`maxDecodeLongSide` 暂定 8192，由 S1-T3 实测确定。
- `KeyModifiers` 的位分配为 command 1、option 2、control 4、shift 8、function 16。keybindings.json 中存的是位掩码。
- `ContentIdentity.cacheKey`：
  - 编码顺序：
    1. 版本前缀 `MacView.ContentIdentity.v1`。
    2. 根：标签 0 为本地；1 为网络，后跟 scheme、host、share；2 为插件，后跟 id。
    3. 层数，以及每层的段数与各段。
    4. 大小、修改时间、校验值标志与校验值。
  - 整数按 64 位小端写入；字符串先写 UTF-8 字节数，再写字节。
  - 缓存键取 SHA-256 的前 16 字节，即 32 位十六进制。
  - 测试里有一个用 Python 独立算出的金样值。改动编码时必须更换版本前缀，旧缓存随之失效。
- `JSONValue`：
  - 编码成普通的 JSON 值，不用 Swift 合成的枚举编码。
  - 解码时依次尝试 null、布尔、数字、字符串、数组、对象，所以 `true` 不会被读成 1。
- `IOPriority`：`Comparable` 让 `visible` 最大（`rawValue` 最小），调度器按 `>` 取最高优先级。
- `Location` 的辅助接口：

  | 接口 | 作用 |
  |---|---|
  | `init(root:layers:)` | `layers` 默认为 `[[]]`，即根本身 |
  | `name` | 末端名称 |
  | `parent` | 所在容器；压缩包内第一层的项，`parent` 是压缩包本身 |
  | `appending(_:)` | 同一层内的下一级 |
  | `appendingLayer(_:)` | 进入末端的压缩包 |
  | `hasPrefix(_:)` | 匹配路径规则 |
  | `description` | 显示用，层与层之间用 `!/` 连接 |

- 公开结构体都有带默认值的初始化器，例如 `DisplayTarget(pixelSize:)` 默认用 Lanczos、不锐化。
- 新增的协议一致性，用于测试断言和前端判断值是否变化：
  - `Equatable`：`VolumeHealth`、`IOError`、`PrefetchPlan`、`SettingsChange`、`ResolveResult`、`PageMove`。
  - `Hashable`：`GlobalSettings`、`PathRule`、`BookMemory`、`KeyBinding`、`MenuNode`、`MenuModel`、`Page`、`Book`。
- 行为约定（写在文档注释里）：
  - `ContainerProvider.children` 按到达顺序分批返回。
  - `SourceRegistry.volumeHealth()` 先给出当前状态，之后每次变化时给出全部卷的状态。
  - `TiledImageSource.tile` 的 `rect` 是原图的像素坐标，`scale` 是输出相对原图的比例。
  - `ReaderSession.open`：
    - 加载全部完成后才返回，期间各属性随事件更新，所以前端在 Task 里调用并观察属性。
    - 再次调用 `open` 时，上一次的加载停止。

## Mock 的用法

```swift
let services = CoreServices.makeMock()      // 样例书架，默认 2.5 张/秒
let session = services.makeSession()
await session.open(MockTree.sample.location("漫画/作品 1.zip"), at: nil)
```

- `MockOptions` 的各项：
  - `tree`：内存目录树。
  - `timing`：`MockTiming`，包括吞吐、延迟、渐进阶段的间隔、枚举的批大小与间隔；`.instant` 去掉全部等待。
  - `failures`：按位置注入任意 `IOError`。
  - `volumeScript`：卷状态脚本，例如 healthy → degraded → unavailable。
  - `settings`：全局设置。
- `MockTree.sample` 是一份样例书架：两套画集、漫画压缩包、分话的目录、动图与视频、单层穿透结构，以及 1 万页的大书。
- 位置写法：
  - `MockTree.location("漫画/作品 1.zip!/001.jpg")` 按 `/` 分段，用 `!/` 进入压缩包。
  - 根是 `nfs://mock.local/mock`。`MockSourceRegistry` 把 `/Volumes/Mock` 下的 URL 映射到这个根。
- 模拟的行为：
  - 读取：
    - 首次访问一个文件时，要在全局队列里排队取得读取名额，默认 2.5 张/秒。
    - 队列按优先级出队；取消的请求直接移出队列。
    - 再次访问只付延迟（20 ms），相当于命中缓存。
  - 元数据（文件头探测）只付延迟，不占读取名额。BookLoader 按阅读顺序分批给出元数据，每批间隔 30 ms。
  - 枚举：每批 64 项，间隔 30 ms。到达顺序是按容器路径确定的乱序，与排序结果不同。
  - 卷不健康时，所有访问抛出 `volumeUnavailable`。卷状态可以按脚本变化，也可以用 `MockEnvironment.setVolumeState(_:stuck:)` 手动设置。
  - 合成图：CoreGraphics 画底色、对角线和边框，CoreText 写上名称、页码和尺寸。
- 只供测试用的接口：
  - `MockImagePipeline.prefetchPlan(for:)`：查看会话当前的预取计划。Mock 只保存计划，不执行预取。
  - `MockSettingsStore.setPathRules(_:)`、`simulateFileError(file:message:)`。
- 简化：
  - 渲染件长边最多 4096，原图也按这个上限渲染，以免占用过多内存。
  - 占位图长边 512、浏览图 2048、缩略图并发 16，这些只是 Mock 的取值，正式值由 S1-T3 确定。
  - BookLoader 只列出书的直接子项，不处理递归。

## 做了什么

- 契约代码：

  | 模块 | 文件 |
  |---|---|
  | MVFoundation | `Location.swift`、`Entry.swift`、`Values.swift` |
  | MVIO、MVMedia、MVPipeline、MVSettings、MVCommands、MVServices | 各模块的同名文件 |
  | MVReading | `MVReading.swift`、`PageFrameEngine.swift`、`ReaderSession.swift` |

- 最小实现：
  - ReaderSession：打开书、全部 PageMove、相邻书、书层设置。
  - CommandRegistry：登记、启用判断、执行；同一标识再次登记时替换处理器，位置不变。
  - BindingResolver：单键绑定。先找当前作用域，再找 global；textInput 不回退到 global。
- MVTestSupport：
  - `MockEnvironment`：各 Mock 共用，持有目录树、卷状态、注入的错误和读取队列。
  - `MockSourceRegistry`、`MockImagePipeline`、`MockSettingsStore`、`MockBookLoader`、`MockBookshelf`。
  - `CoreServices.makeMock(_:)`。
- 测试：

  | 测试目标 | 内容 |
  |---|---|
  | MVFoundationTests | Location 的 JSON 往返与精确 JSON、跨层导航、前缀规则；缓存键的金样值与各字段敏感性；JSONValue 解码；Entry 的计算属性 |
  | MVIOTests、MVMediaTests | 优先级和渲染质量的顺序 |
  | MVSettingsTests | 逐字段合并；书层 JSON 只含覆盖的字段；全局默认值往返与缓存预算 |
  | MVCommandsTests | 登记、启用、替换处理器；作用域回退，textInput 不回退；绑定的 JSON 形状；菜单往返 |
  | MVTestSupportTests | 验收测试。<br>ReaderSession：导航、相邻书、设置、加载错误。<br>来源：分批枚举、压缩包条目、URL 映射、卷脚本。<br>管线：首访限速与重访、优先级插队、取消后出队、错误注入、原图、动图、视频封面、分块、预取计划。<br>设置：分层解析、变化流。<br>阅读：BookLoader 的事件顺序与排序，书架的排序、封面、相邻书和单层穿透。 |

## 证据

- `make test`：12 个测试目标、62 项测试全部通过。
  - MVTestSupportTests 共 20 项，用时 0.69 秒。
  - 验收测试是 `mockServicesDeliverPageFiftyInThreeStages`，用默认时序（2.5 张/秒）：
    1. 用 `CoreServices.makeMock` 打开 100 页的模拟书。
    2. 翻到第 50 页，即 `050.jpg`，原图 3600×5400。
    3. 依次收到占位图 341×512、浏览图 1365×2048、精确图 1200×1800。
- `make build`：App 构建通过，零警告。
- 把全部源文件 touch 后重新执行 `swift build --build-tests`：零警告。
