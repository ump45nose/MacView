# S1-T5 MVPipeline：图像管线

- 完成日期：2026-11-01。
- 实现：`FileImagePipeline`、`PipelineCaches`、`PipelineConfiguration`，以及 `mvbench pipeline`。
- 结果：C3.1–C3.3 通过；C3.4 因没有在线 NFS 挂载而未验证。

## 实现与契约

- 统一内容作业按 `ContentIdentity` 合并文件头和完整文件的消费者；读取期间可提升终点与优先级。同文件的不同渲染件在读完后汇总目标尺寸，共用一次源解码，再生成缩略图、浏览图与显示图。
- 各层按 `ByteSource.identity` 回填，L1 显示图键包含目标尺寸、滤镜及锐化。完整 L0 命中不再次打开源文件；取消时保留已完成的前缀，后续从前缀末尾继续。
- 每个消费者独立取消，只有最后一个消费者离开才取消共享作业。预取按会话整体替换，保留项把优先级变化传给真实 I/O 请求组；批量流逐项交付错误。
- `renditions=[]` 表示只预读原始字节。同一身份的原始字节项和派生件项可以并存，差异计划使用「身份＋renditions」作为内部项键。
- 渐进流按占位、浏览、精确尺寸交付；已有较高质量时跳过较低阶段。冷首图可在精确尺寸交付后继续完成缓存落盘，流完成前等待落盘结果。
- 网络根视频使用 `ByteSourceAsset`；本机及归档内视频使用 provider 的 `fileURL(for:)`。

## 验收证据

| 检查 | 实际结果 |
|---|---|
| C3.1 定向测试 | 14 项全部通过，0.273 秒；最终 DCT 容差与批量交付相关两项回归通过，0.105 秒；编译零警告 |
| C3.2 本地首图 | 10 个不同文件，3600×5400 JPEG → 1707×2560，精确尺寸交付 P50 61.09 ms、P95 **110.50 ms**，预算 150 ms |
| C3.3 缓存首屏 | 10000 项 L2，均匀取 60 项，输出长边 256；10 轮各自新建空 L0/L1，全部交付 P50 19.39 ms、P95 **20.97 ms**，预算 100 ms |
| C3.4 NFS 首访 | **未验证**。挂载表只有 SMB 的 Picture，没有 NFS；没有改挂载或 NAS 配置，也没有进行 NAS 写入 |

独立阶段验收仅执行一次 `make build test`：176 项测试全部通过，零失败、零跳过、零编译警告。同条件独立性能复测：首图 P95 **78.68 ms**，缓存首屏 P95 **19.76 ms**；证据为 [S1-T5-pipeline-independent.json](bench/S1-T5-pipeline-independent.json)。验收后仅修正文档，功能代码未变。

测试覆盖不同渲染件并发的一次读取、一次源解码，元数据只读文件头，实际身份回填，三个交付阶段与质量跳过，预取增删和优先级修改，会话及单订阅取消隔离，取消后的前缀续读，批量单项错误，以及分块、动图、本机/网络/归档视频路由。960×1440 的用例验证 DCT 900×1350 的合法容差放大可以正常完成。

基准 JSON：[S1-T5-pipeline-local.json](bench/S1-T5-pipeline-local.json)。实测机器由工具识别为 **MacBookPro18,1、Apple M1 Pro、8 个性能核心、32 GB 内存、macOS 27.0.1、APFS**；按实际硬件记录。

C3.2 使用仓库 `Fixtures/image/size/3600x5400.jpg` 的 10 个独立副本，每个 848493 字节，属于合成夹具；没有用写真图片代替这项证据。计时从调用 `image` 到收到精确尺寸事件，包含真实来源打开、读取、元数据探测、源解码、缩放和流交付。各文件的管线缓存均未预置；操作系统页缓存未清空。C3.3 使用该图的有效 683×1024 JPEG 渲染件，分别写入 10000 个独立缓存键，计时包含 SQLite 查询、L2 文件读取、JPEG 解码、缩放和全部 60 项交付。

实际命令均从需求 worktree 根运行；构建、模块缓存和临时目录全部位于工作区：

```zsh
stage3_work="$PWD/build/stage3-work"
export TMPDIR="$stage3_work/tmp"
export XDG_CACHE_HOME="$stage3_work/xdg-cache"
export CLANG_MODULE_CACHE_PATH="$stage3_work/clang-module-cache"
export SWIFTPM_MODULECACHE_OVERRIDE="$stage3_work/swift-module-cache"
stage3_flags=(--package-path Packages/MacViewKit --scratch-path "$stage3_work/swiftpm-build" --cache-path "$stage3_work/swiftpm-cache" --config-path "$stage3_work/swiftpm-config" --security-path "$stage3_work/swiftpm-security" --disable-sandbox)
swift build "${stage3_flags[@]}" --product mvbench
"$stage3_work/swiftpm-build/debug/mvbench" fixtures --root "$stage3_work/generated-fixtures"
swift test "${stage3_flags[@]}" --disable-xctest --filter MVPipelineTests
swift test "${stage3_flags[@]}" --disable-xctest --filter 'batchFailureDoesNotInterruptOtherItems|differentFiltersAndSharpeningProduceDistinctL1Entries'
swift build -c release "${stage3_flags[@]}" --product mvbench
"$stage3_work/swiftpm-build/release/mvbench" pipeline --dir "$stage3_work/cold-jpegs" --limit 10 --cached-entries 10000 --repetitions 10 --work-directory "$stage3_work/pipeline-bench" --output docs/reports/bench/S1-T5-pipeline-local.json
```

夹具生成后核对 55 个入库夹具和 8 个本地夹具全部一致。本地夹具经本次新增的 `Fixtures/local/generated` 符号链接供测试使用。临时根及链接在阶段总验收后统一清理；报告与规定 JSON 保留。

## 依赖、偏差与未决项

- 没有新增依赖。复用现有 MVIO、MVMedia、MVCache；既有 GRDB.swift 7.11.1 为 MIT 许可，swift-argument-parser 1.8.2 为 Apache-2.0 许可，已核对依赖中的许可证文件。
- 源解码已经启动后才到达、并超出本轮覆盖尺寸的更大请求，会复用 L0 开始后续解码，不重复源读取。读取期间重叠的不同渲染件已用真实文件计数测试证明一读一解码；此边界已向阶段主控回报。
- NFS 吞吐比及 8–23 MB 写真照片 JPEG 的本地性能尚未实测。`mvbench pipeline --throughput --dir …` 已实现 4 并发、4 MB 块、3 轮交替的原始读取/缩略图吞吐测量，在线 NFS 样本可用时再记录比值；低于 90% 的瓶颈分析留给 S2-T1。
