## 无法生成的格式

| 格式 | 原因 | 需要的样本 |
|---|---|---|
| JXL | ImageIO 能解码，但 `CGImageDestinationCopyTypeIdentifiers()` 不含 `public.jpeg-xl`；本机没有 cjxl | 有损、无损各一张 |
| RAW | ImageIO 不能写 DNG，本机也没有其他编码工具 | DNG、CR3、NEF、ARW 各一张 |
| 带图层的 PSD | ImageIO 写出的 PSD 只有合成图 | 一张含多个图层的 PSD |

样本请放到 `Fixtures/local/samples/`（不入库），用到它们的测试在文件存在时才运行。PSD 本身能生成，即 `image/format/image.psd`。

## 用法

- 读清单用 `Fixtures.manifest()`，按路径取用 `manifest[path:]`，文件位置用 `Fixtures.url(path)`。这些类型在 MVTestSupport。
- 大夹具要先生成：`make bench ARGS="fixtures"`，约 7 秒，峰值内存 1.8 GB。依赖大夹具的测试加 `.enabled(if: Fixtures.hasLocal())`。
- `--verify-only` 只核对，`--skip-local` 只生成入库的夹具。
- 本地样本是 `Fixtures/local/sample-set/0001.jpg … 0085.jpg`。
- 增改夹具：修改 `FixtureCatalog`，重新生成，把夹具和清单一起提交。

## 做了什么

- 清单的类型（MVTestSupport 的 `Fixtures.swift`）：`FixtureManifest`、`Fixture`，以及 `ImageFacts`、`VideoFacts`、`ArchiveFacts`、`DirectoryFacts`。
- 生成器（mvbench 的 `Fixtures/`）：
  - 期望属性由生成参数直接给出，不从生成结果中读取，核对才能发现生成器的错误。
  - 图片用 CoreGraphics 画合成图、ImageIO 编码；WebP 用 cwebp 和 img2webp。
  - 视频用 AVAssetWriter 和 macOS 27 的 `inputPixelBufferReceiver`。原来的 `AVAssetWriterInputPixelBufferAdaptor` 在 macOS 27 已弃用，会产生警告。
  - zip、tar、gzip 的写入器自己实现，以便精确控制要覆盖的特性：ZIP64、数据描述符、GBK 文件名、ustar prefix、pax、GNU 长文件名。
  - 生成器只管理入库夹具的第一级目录和 `local/generated/`，生成前先删掉；`local/` 下的其他内容不动。
- 核对器（`FixtureVerifier`）：
  - 图片用 ImageIO 核对：类型、按方向换算后的尺寸、方向、帧数与各帧时长、循环次数、渐进、颜色模型、位深、透明通道、ICC 名称。方向夹具另按方向解码，取四个象限中心的颜色。
  - 视频用 AVFoundation 核对编码、显示尺寸、旋转、时长和帧率。
  - 压缩包：
    - 用 `/usr/bin/bsdtar` 列出并解出，比对条目的路径、顺序、大小和 SHA-256，嵌套的压缩包递归核对。
    - 单文件 gz 用 `/usr/bin/gzip -dc`。
    - 另外直接读 zip 的中央目录和 tar 头，确认要覆盖的特性确实存在。
    - macOS 的 bsdtar 默认把 `__MACOSX/` 下的 AppleDouble 当作元数据，既不列出也不解出，核对时用 `--options zip:!mac-ext` 关掉。
  - 目录树比对全部后代，含隐藏文件。
- 本地样本：从 `/Volumes/Picture` 只读复制 No.5133 到 `Fixtures/local/sample-set/`，85 张 JPEG，768 MiB，用时 26 秒。复制时 S0-T2 的测量已经结束。
- 测试（mvbenchTests 的 `FixturesTests.swift`）：

  | 测试 | 内容 |
  |---|---|
  | `committedFixturesMatchTheManifest` | 入库的夹具与清单一致 |
  | `localFixturesMatchTheManifest` | 大夹具与清单一致；没生成时跳过 |
  | `committedFixturesStayWithinTwentyMebibytes` | 入库夹具不超过 20 MiB |
  | `regeneratingReproducesTheCommittedManifest` | 在临时目录重新生成，清单与入库的相同，生成结果通过核对 |
  | 其余 4 项 | 方向映射、zip 经 bsdtar 往返、pax 记录长度 |

## 确定性

- 时间戳固定：zip 的 DOS 时间与 tar 的 mtime 都是 2025-01-01 UTC，gzip 的 MTIME 为 0。
- 清单记有压缩包条目的 SHA-256，所以重新生成时，条目里的 JPEG 也要逐字节相同。`regeneratingReproducesTheCommittedManifest` 检查这一点。
- 本机连续生成 3 次，入库夹具逐字节相同，HEIC 和 AVIF 也相同。任务文档不要求硬件编码器的字节一致，测试也不比对它们。
- 系统升级后，如果 ImageIO 的编码结果变了，上述测试会失败并提示重新生成。重新生成后，把夹具和清单一起提交。

## 证据

- `make bench ARGS="fixtures"`：

  ```
  生成用时 7.0 秒
  入库 55 个，3.2 MiB
  本地 8 个，43.5 MiB（local/generated）
  核对用时 0.7 秒，全部与清单一致
  ```

  `/usr/bin/time -l` 测得峰值常驻内存 1.8 GB，来自 20000×20000 的图。
- 确定性：用 `--skip-local --root` 分别生成到两个临时目录，用 `diff -rq` 比较两者，并与 `Fixtures/` 比较，都没有差异。
- 核对器能发现问题：在临时副本里改坏 4 个夹具，核对器全部报出，退出码为 1。
  - 把方向 1 的图复制成 `6.jpg`：报“方向为 1，应为 6”。
  - 改 `stored.zip` 中的一个字节：bsdtar 报 CRC 错误。
  - 改 `pax.tar` 扩展头里的文件名：报条目列表不一致，并解出了清单之外的文件。
  - 删掉 `tree/hidden/.DS_Store`：报缺少该文件。
- `make test`：12 次测试运行全部通过。mvbenchTests 共 30 项，其中夹具相关的 8 项用时 1.2 秒。
- `swift build --build-tests` 与 `make build`：零警告。

## 依赖

- 没有新增 Swift 包依赖。
- 重新生成需要 Homebrew 的 webp 1.6.0（BSD-3-Clause），只作为命令行工具调用，不链接。缺少时，生成器提示 `brew install webp`。

## 与任务文档的偏差

- 增加的夹具：
  - 色彩：Display P3、灰度、CMYK、透明通道、16 位。
  - 动图：APNG、WebP 动图、单帧 GIF、各帧时长不同的 GIF。
  - 视频：m4v，以及轨道变换旋转 90° 的竖屏视频。
  - 压缩包：cbz，以及含 `__MACOSX/` 的 zip。
  - 隐藏文件：`Thumbs.db`。
- PSD 能用 ImageIO 生成，只是没有图层。
- 3600×5400 的 JPEG 只有 848 KB，放在入库夹具里。
