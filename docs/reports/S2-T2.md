# S2-T2 性能验收工具与证据

## 范围与方法

验收脚本通过 Debug 本地套接字驱动隔离数据目录中的 App，逐场景生成 `docs/reports/bench/S2-T2-<场景>.json`。JSON 的 `budget`、`measured` 和 `verdict` 分别记录预算、实测和判定；`environment` 表示环境不满足，`unverified` 表示证据不足。修改前的第一轮仅作对照，见 `docs/reports/bench/round1/`。本轮独立验收基于 `7e42358a838516dcbe9f18a729ca271852beeadd`。

`7e42358` 首轮独立验收的 13 个场景中 3 个通过、8 个环境不满足、2 个因调试响应超时未验证。8 个环境不满足的场景在等待 20 分钟内未满足条件，没有有效测量值。详见 [验收检查记录](bench/S2-stage3-checks.json)。

第一次验收后，录制和诊断工具已在 `26cf278` 修正，见 [超时诊断证据](bench/S2-T3-timeout-diagnosis.json)。`main-thread` 和 `memory-30min` 已在此提交定向复验。结果合计 4 通过、8 环境不满足、1 未通过，跨两个提交；未重跑的 NAS 吞吐、分块取消和面板重启仍归属 `7e42358`。最终环境检查为负载 8.410、屏幕未锁、空闲 262.65 秒、无外接显示器、59.94 Hz；负载超过 6 且刷新率不足 120 Hz，原 8 个场景未补测。G2 未通过，问题交回设计侧。

占位布局的现有证据是 `MVLayoutTests/CollectionLayoutTests.swift` 的宽高比逐批到达测试，以及 [S1-F3 报告](S1-F3.md) C5.1：已排项保持原位；面板自检还检查封面宽高比来源。上述测试证明布局计算规则，正式界面加载图片时屏幕是否不跳仍需目视确认。

缓存实现中 L0 原始字节和 L1 解码结果有独立内存预算，L2 缩略图和 L3 浏览图预算是磁盘预算；预取范围可配置。现有测试覆盖这些预算的配置和生效，但没有证明需求所述缩略图内存缓存、浏览图预载各自具有独立内存预算。建议设计侧按产品需求设计独立预算、调整接口与设置后另派实现。

NAS 的 C1.10 gzip 图集吞吐未验证：共享上的 `.gz` 实际是 RAR 或 7z，用户已确认这两种格式不在支持范围，未向 NAS 写入测试样本。缩略图吞吐与此项分别判定。

本轮 NFS 吞吐三次原始读取分别为 69.25、76.17、73.04 MB/s，缩略图分别为 72.82、69.83、73.57 MB/s；总比值为 0.997024。

主线程定向复验中，另 4 次文件操作来自系统辅助功能本地化、符号辅助描述和 HIToolbox 初始化，原栈保存在 JSON，不能据此声称主线程所有文件 I/O 为零。冷段 60 秒有 3524 个合成事件、666 次位置变化，但窗口未保持前台，仅记录 40 帧、约 0.6 fps，不能替代 120 Hz 前台滚动验收。时基修复后的录制已正常保存并导出；详见 [验收检查记录](bench/S2-stage3-checks.json) 的 `recheck1.mainThread`。

内存定向复验完整运行 1801.606 秒，共 1632 个样本、1066 个动作，没有发生调试响应超时。按每个样本的 elapsed 排除前 300 秒后，1353 个样本的中位数为 2,002,010,112 字节，最小值为 1,659,895,808 字节，最大值为 2,726,199,296 字节；最大偏离中位数 36.173%，出现在 821.585 秒，超出 ±10% 预算。`leaks` 报告 416 项、19,936 字节并返回 1。泄漏项集中于系统 XPC 连接循环，现有栈不足以定位 MacView 代码，也不能因此豁免零泄漏预算；峰值原因未明。详见 [S2-T3 的诊断](S2-T3.md#内存诊断与交回)。

## 真实输入录制（C5.2、C5.12）

两项均需内建屏运行于 120 Hz、屏幕解锁且窗口在前台；录制应由用户真实操作。自动场景及 `--smoke` 空录不替代用户验收。命令在工作区根目录运行，输出放在工作区内，每段使用尚不存在的输出目录。先将临时目录设在工作区：

```sh
mkdir -p "$PWD/build/acceptance/user-tmp"
export TMPDIR="$PWD/build/acceptance/user-tmp"
```

### C5.2 触控板滚动

正式瀑布流各录已缓存和首访一段。脚本完成准备并提示开始后，在 60 秒内用触控板快速来回滚动、甩动惯性和停走，保持窗口在前台；每段结束后检查输出目录的 `hitches.json`、`during.json`，并记录帧数、卡顿次数和帧时间 P99。

```sh
scripts/acceptance/record-trackpad.sh scroll-cached build/acceptance/user-scroll-cached
scripts/acceptance/record-trackpad.sh scroll-cold build/acceptance/user-scroll-cold
```

原 C5.2 还要求画布的砌体、网格、纵向条和横向条分别进行触控板滚动与改尺寸录制，具体命令和锚点目视检查见 [S1-F3 报告的录制步骤](S1-F3.md#给用户的录制步骤c52)，同样使用上述 120 Hz、解锁、前台和工作区临时目录条件。滚动帧时间 P99 预算为 8.33 ms；保留 trace 在工作区，不入库。

### C5.12 停靠操作

脚本准备好带书和面板的窗口并提示开始后，第一段的 60 秒反复将面板标签拖到左、右和底部停靠区，第二段的 60 秒来回拖各区与上下分割的分隔线，保持窗口在前台。

```sh
scripts/acceptance/record-trackpad.sh scroll-cached build/acceptance/user-dock-drag
scripts/acceptance/record-trackpad.sh scroll-cached build/acceptance/user-dock-resize
```

两份 `hitches.json` 的 `phases[0].frameTimeP99` 应 ≤ 8.33 ms，记录帧数与卡顿次数。必要时只结束本次录制启动的 App PID，保留用户已打开的 MacView。

## 验证与清理

- 优化 Debug 构建成功，Swift 编译零警告；Xcode 另打印 CoreSimulator 版本环境诊断，macOS 构建成功。
- `7e42358` 上 `make test`：247 项通过，零警告、零错误。C3.1 的可见请求优先及视频封面优先级测试通过；C3.2 的 100 次预解码命中 P95 ≤ 8 ms，源文件 open/read 增量为 0。工具修复后复用该结果，未重复全量测试。
- 验收脚本判定规则检查 88 项通过。
- 工具修复后优化 Debug 构建零 Swift 警告，判定规则检查 88 项通过；20 次短诊断 `state` 最大 3.063 ms，原内存超时未复现，短测不替代 30 分钟验收。
- 中文和 ASCII 的 Mock 复验均退出 0，但 App 未激活、均跳过字母输入分支，C3.3 未验证；输入源已恢复微信拼音。Viewer 复验退出 6，拖动、单击及分块移开等真实事件未覆盖，预载自检测得 18.07 ms，但运行负载不合格，不能作有效性能结论。Panel 虽退出 0，两次点击退回直接触发行的动作，真实事件路径未验证。详情见 [验收检查记录](bench/S2-stage3-checks.json)。
- 录制脚本 `--smoke` 退出 0，锁屏时取得 0 帧，仅证明流程能结束，不代表帧时间或用户操作通过。
- 隔离 GUI 探路中，测试 App PID 29476 正常退出后，一次原生界面读取自动以无参数重启了工作区 App（PID 29920）。该进程已按 PID 结束，用户原有 PID 72765 未结束。只读元数据检查显示默认 `~/Library/Application Support/MacView/session.json` 及默认缓存目录的修改时间与此次启动吻合，说明默认会话和缓存被触及；没有旧会话备份，未擅自回退或删除已有用户文件。此前命令行测试实例仍使用隔离的 support、cache 和 layout 参数，但不能将整轮称为完全隔离。后续 GUI 应由人工先激活隔离实例，并通过调试接口驱动，避免原生绑定自动重启。
- 主控卸载测试 NFS 挂载成功，清理 `build/acceptance`、`build/selftest-w31`、`build/DerivedData-profile`、`build/stage3-work`；正式证据 JSON 保留。独立 C3.7 检查通过：没有测试挂载、代理、任务 App、xctrace 录制或 caffeinate 残留；用户原有 MacView PID 72765、10 个 SMB 挂载、主 `build/DerivedData` 和默认 Library 中已有文件保留。见 [验收检查记录](bench/S2-stage3-checks.json)。
