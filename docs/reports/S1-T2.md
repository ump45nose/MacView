# S1-T2：压缩包与嵌套

2026-11-01，MacPro。状态：已完成；本地归档验收通过，NAS 吞吐 C1.10 因 NFS 未在线而未验证。

## 实现

- `ArchiveProvider(fileSystem:extractDirectory:extractBudget:)` 实现完整 `ContainerProvider` 契约。登记来源优先于文件系统；压缩包作为容器时列出内容，`entry/open/fileURL` 对压缩包文件本身仍交给所在层。provider 不持有 registry。
- ZIP 从结尾与中央目录建立索引，支持 ZIP64、data descriptor、stored 和 deflate。无注释的常见文件先读最后 22 字节；扫描得到的尾部缓冲可复用于中央目录和 ZIP64 记录。UTF-8 标志优先，否则按 GB18030 解码，失败后按 CP437。完整读取校验 CRC32。
- stored 条目以外层 `ByteSource` 的范围映射读取，不先解出；deflate 用系统 Compression 流式解码，4 MB 输入块、256 KB 输出块，范围读取只收集请求区间。优先级、请求组和 Task 取消传给底层读取。
- tar 首次顺序扫描头部，校验头部和范围，支持 ustar prefix、pax `path/size/mtime`、GNU 长文件名；pax 时间按十进制转换为整数纳秒，支持负数并检查溢出；补齐没有物理目录记录的祖先目录，保留元数据文件。
- gzip 流式解出并校验头部、CRC32 与 ISIZE，`.gz` 根据 tar 头部校验和识别内容；非 tar 内容作为单个文件。嵌套 stored 包始终保持映射，非 stored 内包先解出。
- 内存按 `ContentIdentity` 保留最近 16 份索引，索引不持有解出文件租约。解出缓存启动时清空，按字节预算与访问顺序淘汰；`ByteSource` 租约存活期间保护对应文件，释放后恢复预算。写入、同步、改名和淘汰清理走专用 I/O 队列；取消或失败会清理部分文件。

## 依赖与范围

没有新增第三方依赖。解码使用 macOS 系统 Compression 框架，校验与格式解析在模块内完成；没有调用 bsdtar、libarchive 或按路径打开归档的库。格式字段参考 [PKWARE APPNOTE 6.3.10](https://pkware.cachefly.net/webdocs/casestudies/APPNOTE.TXT)。

## 边界与未决项

- NFS 挂载未在线，NAS 吞吐 C1.10 未验证。
- `fileURL` 只返回 URL，契约没有关闭/释放接口。provider 保留最近一次交付 URL 的租约，直到下次 `fileURL` 交付或 provider 释放，保证该次交付的文件可用；不承诺多个外部程序可无限期持有旧 URL。`ByteSource` 的使用周期则有精确租约保护。
- 正在使用的文件可以暂时使缓存超过预算；租约释放后恢复预算。当前公开接口无需增补。
- 临时日志与重复测试文件在交回前清理；规定的测试与本报告保留。实现范围与阶段设计一致，未进行 NAS 写入或挂载变更。
