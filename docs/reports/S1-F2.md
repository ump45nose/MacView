# S1-F2 停靠面板框架：报告

## 结论

- C5.9 布局变换的单元测试、`make build`、`make test` 均通过，零警告。
- C5.10、C5.11 已由停靠自检自动验证，三个阶段全部通过。
- 屏幕锁定，App 无法激活，以下两部分需要解锁后补测：
  - 真实的鼠标拖动；
  - 真实的全屏过渡。
- C5.12 需要用户录制，步骤见“需要用户动手的验收”。

## 做了什么

- **布局模型**：`Packages/MacViewKit/Sources/MVLayout/DockLayout.swift`，纯计算，不依赖 AppKit。
  - `DockLayout`：三个区（`DockArea`：面板栈、形式、选中项、分割比例、尺寸、折叠）、浮动面板（`FloatingPanel`）、隐藏的面板、各面板的视图设置。
  - 变换都是返回新值的方法：
    - `moving(_:to:)`：移动到区内的位置，或拖出浮动；从浮动拖回也用它。
    - `inserting(_:at:settings:)` 与 `removing(_:)`：跨窗口移动的两端。
    - `docking(_:)`：浮动面板回到原来的区。
    - `togglingStyle`：标签页与上下分割互换。
    - `togglingArea`、`togglingAllAreas`、`togglingPanel`：显示与隐藏。
    - `resizing`、`reweighting`、`selecting`、`movingFloating`、`settingSettings`。
    - `adoptingFloating(of:)`：浮动面板全应用共享，窗口采用新的浮动列表。
    - `sanitized(knownPanels:)`：整理从文件读入的布局。
  - `DockTarget.area(edge, index:)` 中的 `index` 是可见面板中的位置。同一区内移动时，先按移走之前的列表找到“排在谁之前”，位置不会错一格。
- **App 侧**：`App/Dock/`。
  - `DockPanel` 协议与 `DockPanelType` 登记，见 `DockPanel.swift`：
    - 登记项：标识、标题、SF Symbol、显示/隐藏命令、默认区、创建方法；
    - 视图设置是 `Codable` 的关联类型，经 JSON 编解码；
    - `bind(to:)` 指定作用的窗口。
  - `DockPanels.all` 登记两个占位面板（`PlaceholderPanel`）。占位面板标出当前作用的窗口，带一项“样式”设置，用来验证编解码。
  - `DockContainerView`：
    - NSSplitView 分左、中、右三栏，底部区在中间栏下方，中间是页面视图；
    - 放置目标的计算与指示；
    - 全屏自动隐藏。
  - `DockAreaView`：一个区的面板栈。标签页形式是标签行加当前面板，上下分割形式用 NSSplitView。右上两个按钮分别切换形式、隐藏停靠区。
  - `DockTabView`：面板标签。单击选中，拖动发起 NSDraggingSession，右键菜单可以移到其他区、浮动、隐藏。
  - `FloatingPanelWindow`：浮动面板，是 NSPanel。
    - 标题条上是标签和“停靠回窗口”按钮；拖动标签可以放进任一窗口的停靠区。
    - 关闭按钮只隐藏面板，位置保留。
  - `WindowDock`：一个窗口的停靠区与面板实例。
  - `DockCoordinator`：全应用唯一。
    - 读写 `layout.json`，用 `JSONDocumentStore<DockLayout>`，版本 1。
    - 管理共享的浮动面板，跟随活动窗口。
    - 处理跨窗口移动，去抖 500 ms 保存，退出前立即保存。
- **接入**：
  - `ReaderWindowController` 把停靠容器作为主视图，页面视图放在中间栏，并处理成为主窗口、进入/退出全屏、关闭这几个通知。
  - `AppDelegate` 创建协调者，退出前调用 `flush()`。
  - `FileErrorBanner`（`App/Shell/`）是设计稿“配置文件解析失败”中的提示条。
- **命令**：
  - 新增 App 命令 `dock.left.toggle`、`dock.right.toggle`、`dock.bottom.toggle`。
  - Core 已有 `panel.docks.toggle`（Tab）、`panel.bookshelf.toggle`（⌥⌘1）、`panel.pageList.toggle`（⌥⌘2），本任务登记了它们的处理器。
  - `CommandCatalog` 把这几项从“窗口”菜单移到“显示”菜单末尾：停靠区一组，面板一组。
- **本地化**：String Catalog 新增 37 个键，均有英文。

### 停靠自检（C5.10、C5.11）

入口在 `App/Debug/DockSelfTest.swift`（Debug 构建）。

拖动手势本身（NSDraggingSession 的鼠标跟踪）无法在锁屏下合成，所以自检从手势之下的同一条路径驱动：

1. 按容器坐标调用 `showDropIndicator(at:)`，求出放置位置并显示指示。拖动经过时的 `draggingUpdated` 走的是同一个方法。
2. 依次调用 `beginDrag` → `drop` → `endDrag`，与真实拖放调用的方法相同。拖出浮动走 `endDrag(accepted: false)`。

命令如下，在 worktree 根目录执行：

```sh
make build
APP=$PWD/build/DerivedData/Build/Products/Debug/MacView.app
OUT=$(mktemp -d)
open -n -W --stdout $OUT/main.log -a $APP --args -MVDockSelfTest main -MVSelfTestOutput $OUT -MVLayoutFile $OUT/layout.json
open -n -W --stdout $OUT/restore.log -a $APP --args -MVDockSelfTest restore -MVSelfTestOutput $OUT -MVLayoutFile $OUT/layout.json
printf '{ "version": 1, "value": { "left": ' > $OUT/layout.json
open -n -W --stdout $OUT/corrupt.log -a $APP --args -MVDockSelfTest corrupt -MVSelfTestOutput $OUT -MVLayoutFile $OUT/layout.json
grep -hE "PASS|FAIL|SKIP|SELFTEST" $OUT/*.log
```

结果（2026-11-01，屏幕锁定）：

- main：54 项 PASS，2 项 SKIP（真实全屏的进入与退出）。
- restore：6 项 PASS。
- corrupt：4 项 PASS。
- 三个阶段都输出 `SELFTEST OK`。

另外：

- S1-F1 的外壳自检 `-MVSelfTest YES` 仍是 `SELFTEST OK`。
- 英文环境（`-AppleLanguages "(en)"`）下，停靠区、占位面板和错误提示条的文字都是英文。

## 自行决定的事项

- **占位面板沿用正式标识**：两个占位面板用正式的标识 `bookshelf`、`pageList`，命令也用 Core 已有的 `panel.bookshelf.toggle`、`panel.pageList.toggle`。S2-F2 只需替换 `DockPanels.all` 中的创建方法和面板类型；`layout.json` 和快捷键都不变。
- **“折叠”即隐藏**：折叠一个区，就是让它不占空间，可以通过三种方式：区头的隐藏按钮、显示命令、把分隔线拖到边缘。没有做只剩标题条的折叠形态。
  - 隐藏面板时保留它在栈中的位置。
  - 区里没有可见面板时，区不占空间；拖动面板时，这个区所在的边缘仍可放置。
- **浮动面板与窗口布局的关系**：
  - 每个窗口的布局只有停靠区；浮动面板以协调者的 `current` 为准。
  - 面板浮动后，其他窗口中停靠着的同一面板随之移走。拖回某个窗口后，其他窗口不会自动出现这个面板，要用命令显示，它会放进默认区。
- **默认布局的含义**：`current` 是最近一次改动所在窗口的完整布局。它既是新窗口套用的默认布局，也是写进 `layout.json` 的内容。
  - 外部修改 `layout.json` 不套用到已打开的窗口，新窗口会读到。
  - `layout.json` 解析失败后，第一次调整布局会覆盖这个文件，提示条上写明了这一点。
- **视图设置的存放**：停靠面板的设置存在 `DockLayout.settings`，浮动面板的存在 `FloatingPanel.settings`，设置随面板移动。某个面板的设置无法解码时，用默认设置，并显示错误提示条。
- **面板实例在移动时保留**：协调者在一轮变换中用 `pool` 交接实例，所以面板在区之间、窗口之间、停靠与浮动之间移动时，视图和状态都保留。
- **识别用户拖动分隔线**：只有同时满足三个条件，才记录为用户拖动：
  - 通知带分隔线序号；
  - 当前事件是本窗口的鼠标事件；
  - 不在窗口缩放中，也不是程序在设置位置。

  只看分隔线序号不够：NSSplitView 初次布局时也会发带序号的通知，实测会把左区记成宽 0 并折叠。
- **浮动面板的行为**：
  - `hidesOnDeactivate`：App 失去焦点时隐藏，与系统调色板一致。
  - `fullScreenAuxiliary`：可以浮在全屏窗口之上。
- **Esc 取消拖动**：拖动结束时，如果当前事件是 Esc 按键，视为取消，不浮动。这一判断没有实测。
- **新增设计令牌**：`Theme` 补了设计稿中的 `well`、`selected`、`accent`、`accentSoft`、`dangerSoft`。

## 与任务文档的偏差

- 布局方案的命名保存与切换不在本任务范围（S4-F3）。
- 新增的公开接口还没有同步到 `docs/architecture.md` §4。它们是 MVLayout 的 `DockLayout`、`DockArea`、`DockFrame`、`FloatingPanel`、`DockTarget`、`PanelPlacement`、`PanelID`、`DockEdge`、`DockStackStyle`，按阶段设计由 W5.4 统一写入。§3.8 需要补充的结论见上一节。

## 未决问题

1. `JSONDocumentStore` 给出的错误位置是固定的中文“第 N 行，第 M 列”，英文环境下提示条里这一段仍是中文。它属于 MVSettings（S1-T7），不在本任务边界内。
2. 自检中发现：在主队列的任务里（例如 `Task { NSApp.terminate(nil) }`）调用 `terminate`，会卡在 `terminateLater` 的等待中，因为退出前保存布局的任务也要在主队列上运行。菜单的“退出”不受影响。如果以后有命令经 `CommandDispatcher`（Task）调用 `terminate`，要改为经 run loop 调用，例如 `perform(_:with:afterDelay:)`。

## 需要用户动手的验收

前提：解锁屏幕并保持亮屏，断开 60 Hz 的外接显示器，命令在 worktree 根目录执行。下面用临时的布局文件，不影响自己的 `~/Library/Application Support/MacView/layout.json`。

### 1. 真实拖动与全屏（C5.10）

```sh
make build
APP=$PWD/build/DerivedData/Build/Products/Debug/MacView.app
mkdir -p /tmp/mv-dock && open -n -a $APP --args -MVLayoutFile /tmp/mv-dock/layout.json
```

1. 按住左区的“书架”标签，拖到右区的标签行。拖动中应出现标签间的 Clay 竖线，松开后右区有两个标签。
2. 继续拖“书架”经过窗口下边缘，应出现“放到底部”的浅 Clay 区域，松开后停靠到底部区。
3. 点右区右上角的分割按钮，改为上下分割。把一个标签拖到两格之间，应出现横线。再点一次，切回标签页。
4. 把一个标签拖到主视图中央或窗口外松开，应成为浮动面板。拖动它标题条上的标签，放回任一停靠区。也可以点浮动面板右上角的“停靠回窗口”。同时确认：
   - 拖动时的标签图像不是上下颠倒的；
   - 按 Esc 取消拖动时，面板不会浮动。
5. 按 ⌘N 打开第二个窗口，把一个面板拖出成浮动面板，然后在两个窗口之间切换。浮动面板上的“作用于：…”应跟着变化。在窗口 2 隐藏左区，窗口 1 不变。
6. 拖动左区、右区和底部区的分隔线改尺寸；拖到边缘时区折叠。然后用“显示 › 显示或隐藏左侧停靠区”恢复。
7. 按 ⌃⌘F 进入全屏，三个区应隐藏。鼠标移到屏幕左、右、下边缘时对应的区浮出，移开后收回。退出全屏后布局与之前相同。
8. 用真实键盘重跑停靠自检（见“证据”中的命令），确认没有 SKIP。运行期间不要切换到其他 App。

### 2. Animation Hitches 录制（C5.12）

用优化构建，与 S1-F3 相同：

```sh
xcodegen generate --quiet
xcodebuild -quiet -project MacView.xcodeproj -scheme MacView -configuration Debug \
  -destination "platform=macOS,arch=$(uname -m)" -derivedDataPath build/DerivedData-profile SWIFT_OPTIMIZATION_LEVEL=-O build
APP=build/DerivedData-profile/Build/Products/Debug/MacView.app/Contents/MacOS/MacView
rm -rf /tmp/mv-dock && mkdir -p /tmp/mv-dock
```

录两段，每段先打开一本书，让主视图有内容（⌘O 只能选 Mock 目录；不打开书也可以，空状态同样参与布局）：

```sh
# 拖动面板 30 秒：窗口出现后，反复把标签在左区、右区、底部边缘之间拖动，并在区上停留移动，让放置指示不断更新
xcrun xctrace record --template 'Animation Hitches' --time-limit 30s --output dock-drag.trace --launch -- $APP -MVLayoutFile /tmp/mv-dock/layout.json
# 改尺寸 30 秒：来回拖左区、右区、底部区的分隔线，以及上下分割中两格之间的分隔线
xcrun xctrace record --template 'Animation Hitches' --time-limit 30s --output dock-resize.trace --launch -- $APP -MVLayoutFile /tmp/mv-dock/layout.json
python3 -I scripts/canvas-hitches.py dock-drag.trace - docs/reports/bench/S1-F2-drag.json
python3 -I scripts/canvas-hitches.py dock-resize.trace - docs/reports/bench/S1-F2-resize.json
```

判定与记录：

- 两份 JSON 的 `phases[0].frameTimeP99` 都应 ≤ 8.33 ms。
  - 阶段名会显示为“手动滚动”，这是 `-` 模式的固定名称。
  - 拖动时，帧时间统计的是 MacView 提交的帧，拖动图像由系统合成。
- 把两份 JSON 中的帧数、hitch 数、帧时间 P99 写进本报告。
- 录制文件很大，不入库。
