# S1-T3 MVMedia：探测、解码与渲染件

前置：G0。状态见 [roadmap](../roadmap.md)。

## 目标

实现只针对内存数据的探测与解码：从文件头得到元数据，按显示需要的尺寸解码并重采样，提供原图、超大图分块、动图帧和视频封面，并选定渲染件的编码格式。MVMedia 不做 I/O，数据由调用方（S1-T5 的管线）读好交进来。

## 范围

- 探测：
  - 输入文件头的 `Data`，从 64 KB 起，不够时告诉调用方需要多少，上限 1 MB。
  - 用 `CGImageSourceCreateIncremental` 得到 `ImageMetadata`：按 EXIF 方向换算后的尺寸、帧数、拍摄时间、色彩空间名称。
  - 视频由调用方给出 `AVAsset`（网络卷上经 S1-T1 的读取桥），取时长和按 preferredTransform 换算后的尺寸。
- 显示尺寸解码：
  - `CGImageSourceCreateWithData` + `CGImageSourceCreateThumbnailAtIndex`，参数 MaxPixelSize、CreateThumbnailWithTransform、ShouldCacheImmediately。
  - 再按 `DisplayTarget` 的滤镜精确缩放：Lanczos 用 vImage 或 MPS（实测选一个），最近邻直接缩放；`sharpen > 0` 时缩小后锐化。
  - 输出已解码、由 IOSurface 支撑的 `CGImage`，保留 Display P3 等宽色域；主线程设置为图层内容时不再触发解码。
  - 解码在有并发上限的专用队列上执行，上限默认为性能核心数，可配置。
- 原图与超大图：
  - `maxDecodeLongSide` 以内解码原图。
  - 超过纹理上限（`MTLDevice` 的最大纹理尺寸）或内存门限的图提供 `TiledImageSource`。实现方式实测确定，候选：预先解出几级降采样金字塔并切块缓存在临时文件；或按行带解码。以 20000×20000 夹具为准，记录首屏时间和峰值内存。
- 动图：GIF、APNG、动图 WebP 的 `AnimatedFrameSource`，按需逐帧解码，帧时长按各格式的规则读取（含 GIF 过短时长的常规修正）。
- 视频封面：AVAssetImageGenerator 取 1 秒处和 10% 处中较早的一帧，按 maxPixel 生成。
- 渲染件编码：
  - 缩略图（长边 1024 px）和浏览图（能放进最大显示器的像素尺寸）在 HEIC 与 JPEG 之间选择。
  - 在秀人样本（`Fixtures/local/sample-set/`）上测编码用时、文件大小、解码用时和主观画质（同等质量参数下与原图的 SSIM 或 PSNR），按“编码用时不成为管线瓶颈、解码用时最短”选定，写进报告。
- mvbench：`mvbench media`，对一组文件测探测、显示解码、重采样和编码的用时分布。

## 不做

- 读文件、缓存和调度（S1-T1、S1-T4、S1-T5）。
- RAW 的显影参数、PSD 图层：只用 ImageIO 给出的合成图。
- 视频播放（S2-F1）。

## 验收

- `make test` 通过，零警告。
- 夹具清单中的每个图片都能探测和解码，元数据与清单一致；EXIF 方向 1–8 解码后的朝向一致（与方向 1 的参考图逐块比较）。
- 动图夹具的帧数和帧时长与清单一致；视频夹具的时长、尺寸与清单一致，能生成封面。
- 3600×5400 基线 JPEG（数据已在内存）解码到 2560 px 长边并完成 Lanczos 缩放：P95 ≤ 100 ms，为本地首显 150 ms 留出读文件和上屏的时间。
- 20000×20000 夹具：首个可显示的分块 ≤ 500 ms，峰值内存 ≤ 1 GB。
- 输出图像在主线程设置为 `CALayer.contents` 时没有额外解码（Instruments 或 signpost 证据）。
