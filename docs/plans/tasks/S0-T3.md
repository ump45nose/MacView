# S0-T3 测试夹具与本地样本

前置：S0-T1。状态见 [roadmap](../roadmap.md)。

## 目标

为所有后续任务提供一套共用的测试数据，以及一份记录期望属性的清单。

## 范围

`mvbench fixtures` 一条命令生成全部夹具，内容如下。

- 图片格式：
  - JPEG（基线、渐进）、PNG、HEIC、TIFF、GIF 动图、APNG。
  - WebP：用已安装的 cwebp 生成。
  - AVIF、JXL：系统能编码时生成。
- 图片尺寸：
  - 小图、3600×5400、20000×20000。
  - 多种宽高比，包括超宽和超长。
  - EXIF 方向 1–8，用 ImageIO 写入。
- 视频：H.264 和 HEVC 编码的 mp4/mov，每段几秒，用 AVAssetWriter 生成。
- 压缩包：
  - zip：stored 与 deflate、ZIP64、data descriptor、UTF-8 文件名、不带 UTF-8 标志的 GBK 文件名、内含子目录。
  - tar：ustar、pax、长文件名。
  - tar.gz、单文件 .gz、zip 套 zip（内层分别为 stored 和 deflate）。
- 目录树：
  - 深层结构、1 万项的目录。
  - 单层穿透结构：只含一个子文件夹且没有媒体。
  - 隐藏文件：`._*`、`.DS_Store`、`.url`。
- 清单 `Fixtures/manifest.json`：记录每个夹具的用途与期望属性，例如：
  - 像素尺寸（按方向换算后）与方向。
  - 帧数与时长。
  - 压缩包的条目，以及解码后的文件名。
- 存放：
  - 提交到 `Fixtures/` 的夹具总量不超过 20 MB。
  - 大夹具（20000×20000 的图、1 万项的目录、视频等）生成到 `Fixtures/local/`。
- 本地样本：从 NAS 只读复制一个图集到 `Fixtures/local/sample-set/`，不要和 S0-T2 的测量同时进行。
- 无法在本地生成的格式（RAW、PSD 等）记入报告，由用户提供样本放进 `Fixtures/local/`。

## 不做

- 提交任何用户图片，或从网络下载样本。
- 解码、压缩包读取等正式实现（S1）。

## 验收

- `swift test` 中的夹具完整性测试通过：清单中的每个夹具都存在，且属性与清单一致（用 ImageIO、AVFoundation 和系统工具核对）。
- 重复生成得到相同的属性。硬件编码器产生的字节不要求一致。

- `mvbench fixtures` 子命令。
- `Fixtures/` 中的小夹具与清单。
- 夹具完整性测试。
- `docs/reports/S0-T3.md`，记录无法生成的格式。
