# S1-T5 MVPipeline：图像管线

前置：S1-T1、S1-T3、S1-T4。状态见 [roadmap](../roadmap.md)。

## 目标

实现 `ImagePipeline`：串联 I/O、解码和各级缓存，一次读取产出全部渲染件，按阶段渐进交付，并按会话应用预取计划。达到本地首显和已缓存目录的验收预算，给出 NAS 首访吞吐的首次测量。

## 范围

- 取图路径：L1 → L2/L3 → L0 → 读文件（S1-T1）→ 解码（S1-T3）→ 回填各层。
- 一次读取，多个产出：
  - 读完一个文件后，在同一份数据上生成元数据、缩略图和浏览图（L3 开启时），写入 L2/L3 与索引；原始字节留在 L0。
  - 同一 `ContentIdentity` 的并发请求合并为一次读取和一次解码，各调用方分别取所需的渲染件。
- 接口语义（§4 `ImagePipeline`）：
  - `metadata`：先查索引；没有时只读文件头探测，不读整个文件。
  - `thumbnail`/`thumbnails`：批量请求按优先级排进调度器，结果按到达顺序流式返回；单项失败不影响其余项。
  - `image(for:target:allowOriginal:)`：依次交付缩略图放大的占位 → 浏览图 → 精确尺寸；已有更高质量的结果时跳过低质量阶段。主区瀑布流按列宽调用时，管线按目标尺寸在缩略图、浏览图和原图之间选择来源。
  - `tiledSource`、`animatedFrames`、`videoPoster`：接 S1-T3 的实现，数据经调度器读取；网络卷上的视频经 S1-T1 的读取桥。
- 预取计划：
  - `setPrefetchPlan` 以会话为单位整体替换：移除的取消，保留的改优先级，新增的入队。
  - `cancelAll(session:)` 取消该会话的全部请求，不影响其他会话。
  - 预取产出只写缓存，不交付给任何调用方。
- 取消：调用方的 Task 取消会传到调度器；排队的直接出队，正在读的在块间停下，已读到的字节仍放进 L0。
- 错误：单项错误按 `IOError` 原样抛出，卷的 degraded 状态不在管线里重复判断。
- mvbench：`mvbench pipeline`，对一个目录测首访缩略图吞吐（张/秒、MB/s）与同一时段的原始读取吞吐（S0-T2「原始读取吞吐的测法」：4 并发、4 MB 块、3 轮中位数，交替测），以及重访时首屏 60 张的用时。

## 验收

- `make test` 通过，零警告。测试覆盖：同一文件的并发请求只读一次、三个阶段的交付顺序、预取计划的增删改、会话间取消互不影响、单项错误不中断批量流。
- 本地 SSD：未缓存的 3600×5400 JPEG，`image(for:)` 交付精确尺寸 ≤ 150 ms（P95，10 次，各次用不同文件）。
- 已缓存目录：1 万项目录，首屏 60 张缩略图从调用到全部交付 ≤ 100 ms。
- NAS 首访（NFS，秀人样本，只读）：缩略图生成吞吐与原始读取吞吐之比写进报告。达不到 90% 时给出瓶颈分析，留给 S2-T1 调优，不阻塞本任务。
