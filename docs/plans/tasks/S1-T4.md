# S1-T4 MVCache：内存与磁盘缓存、索引

前置：G0。状态见 [roadmap](../roadmap.md)。

## 目标

实现四层缓存和 SQLite 索引，使重访的目录和图片不再读 NAS：已缓存目录重新打开后 100 ms 内能显示首屏缩略图。

## 范围

- 内存层：
  - L0：原始文件字节，默认 512 MB。L1：解码结果，默认 min(2 GB, 10% 物理内存)。
  - 按字节计成本的 LRU，预算可以运行时修改。
  - 系统内存压力（`DispatchSource.makeMemoryPressureSource`）为 warning 时收缩到预算的 50%，critical 时收缩到 25%。
- 磁盘层：
  - L2 缩略图，默认 10 GB；L3 浏览图，默认 50 GB，可关。
  - 文件以 `ContentIdentity.cacheKey` 命名，按键的前缀分子目录。
  - 写入：先写临时文件，再改名，最后更新索引。读取以索引为准；崩溃后索引不能指向缺失或不完整的文件。
  - 超出预算时按访问时间淘汰。访问时间批量写回索引，不在每次读取时写库。
  - 启动时不扫描缓存目录。崩溃留下的孤儿文件（已改名、未入索引）要有回收途径，例如淘汰时按子目录抽查，不能无限累积。
- 索引（`index.sqlite`，GRDB.swift）：
  - 元数据：cacheKey → `ImageMetadata`，按书批量查询。
  - 目录列表：容器 Location → 条目列表与目录的修改时间。
  - L2/L3 的位置、大小与访问时间。
  - 本任务引入 GRDB.swift（MIT），记录版本；S1-T7 共用。
- 目录缓存：`cachedChildren(of:)` 立即返回上次的结果；调用方在后台重新枚举后，以 `update` 写回，并得到增删的差异。
- 存储接口按值类型泛型化，具体类型由 MVPipeline 指定；本模块不依赖 MVMedia 和 MVIO。

## 验收

- `make test` 通过，零警告。单元测试覆盖：LRU 顺序与成本、预算修改、内存压力收缩、磁盘淘汰、访问时间批量写回、目录缓存的差异。
- 崩溃安全：测试进程在写入循环中被 SIGKILL 后重新打开，索引中的每一项都能完整读出；孤儿文件能被回收。
- 性能（本机 SSD，L2 中已有 1 万个缩略图）：
  - 一个 1 万项目录的缓存列表与元数据，一次查询 ≤ 20 ms。
  - 并发读出首屏 60 个缩略图文件 ≤ 30 ms。解码用时计入 S1-T5 的 100 ms 验收。
- 磁盘层的总大小在预算之内，淘汰期间并发读写不出错。
