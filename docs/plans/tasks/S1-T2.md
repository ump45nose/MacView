# S1-T2 MVArchive：压缩包与嵌套

前置：G0（读取经 S1-T1 的 ByteSource；S1-T1 完成前用内存或文件实现的 ByteSource 开发）。状态见 [roadmap](../roadmap.md)。

## 目标

把 zip/cbz、tar、tar.gz 和 .gz 当作目录浏览，嵌套的压缩包和压缩包内的子目录都能进入。所有读取都经 `ByteSource`，因此 NAS 上的压缩包同样受调度、取消和期限约束。

## 范围

- ArchiveProvider（`ContainerProvider` 实现），处理层数大于 1 的 Location：
  - `children(of:)`：压缩包内的目录树，按目录分批返回。
  - `entry(at:)`：条目的 `ContentIdentity` 用条目的大小、修改时间，zip 另带 CRC32 作 checksum。
  - `open(_:)`：条目的 `ByteSource`。
  - `fileURL(for:)`：解出到 `~/Library/Caches/MacView/extract/`，供 AVFoundation 和外部程序使用。
- zip：
  - 从文件末尾读中央目录，支持 ZIP64 和 data descriptor。
  - stored 条目直接映射为外层的偏移区间；deflate 条目用 Compression 框架流式解压。
  - 文件名带 UTF-8 标志（bit 11）时按 UTF-8 解码，不带时按 GB 18030 解码，失败再按 CP437。
- tar：ustar、pax 扩展头（path、size、mtime）、GNU 长文件名。tar 没有中央目录，首次打开时顺序扫描一遍头部，记下每个条目的偏移。
- gzip：
  - `.tar.gz`/`.tgz` 和 `.gz` 都先流式解压到 `extract/` 下的临时文件；`.gz` 解压后看内容是否为 tar（ustar 魔数或合法的头部校验和），是就按 tar 浏览，否则作为单个文件。
  - 解压过程可以取消，部分文件不留下。
- 嵌套：内层压缩包是 stored 时直接映射为外层的偏移区间，否则先解出到 `extract/`。
- 临时目录：
  - 容量预算默认 10 GB，按最近使用淘汰；正在使用的文件不淘汰。
  - 启动时删除上次留下的 `extract/` 内容。
- 不使用 bsdtar、libarchive 或按路径打开文件的库；`/usr/bin/bsdtar` 只在 S0-T3 的夹具校验中使用。
- 过滤 `__MACOSX/`、`._*`、`.DS_Store`、`Thumbs.db` 等不在本任务做，由 S1-T6 的 BookLoader 统一处理；本任务如实列出条目。

## 不做

- rar、7z、加密压缩包（requirements.md「不做」）。
- 写入或修改压缩包。
- 解出结果的持久缓存（L2/L3 存的是渲染件，不是解出的文件）。

## 验收

- `make test` 通过，零警告。
- 夹具清单里的每个压缩包：条目列表、名称（含 GBK 文件名）、大小与清单一致，每个条目读出的内容与清单记录的校验值一致。
- zip 套 zip（stored 与 deflate 各一）能进入内层并读出图片；stored 的内层不产生解出文件。
- 读 stored zip 中的一个条目，经 ByteSource 读取的字节数不超过条目大小加 64 KB。
- 取消 `.gz` 解压后，`extract/` 中没有残留文件；超过预算时按最近使用淘汰。
- 以 NAS 上的一个 `.gz` 图集（只读）实测：能作为 tar 浏览，解压吞吐不低于同一时段原始读取吞吐的 90%。
