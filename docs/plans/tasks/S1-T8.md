# S1-T8 MVServices 组合根与集成测试

前置：S1-T1、S1-T2、S1-T5、S1-T6（S1-T7 经 S1-T6 间接要求）。状态见 [roadmap](../roadmap.md)。

## 目标

实现 `CoreServices.make`，把真实的各模块连起来，负责启动、退出和内存压力处理；用跨模块集成测试证明 Core 作为整体能用，作为关口 G1 的依据。

## 范围

- `CoreServices.make(configuration:)`：
  - 建目录（support、cache、extract），打开 `index.sqlite` 和 `state.sqlite`。
  - 创建 IOScheduler、SourceRegistry（登记 FileSystemProvider 与 ArchiveProvider）、各级缓存、ImagePipeline、SettingsStore、CommandRegistry（登记 Core 侧的默认命令清单）、Bookshelf、BookLoader。
  - 任何一步失败都抛出带原因的错误，App 显示错误而不是静默退回 Mock。
- 启动预算：`make` 在本机 SSD 上 ≤ 200 ms，不扫描缓存目录，不访问网络卷。
- `shutdown()`：保存书记忆和待写的访问时间，关闭数据库；最多等 1 秒，不等被卡住的 I/O 线程和辅助进程。
- 内存压力：订阅系统事件，统一收缩 L0/L1，并取消 background 优先级的预取。
- `makeSession()`：用真实的 BookLoader、SettingsStore、Bookshelf 创建会话。
- 集成测试（`MVServicesTests`，用夹具和临时目录作 support/cache）：
  1. 打开 zip 书，枚举、排序、探测完成，翻到第 10 页，取到精确尺寸图。
  2. 为整本书生成缩略图；重建 CoreServices 后再取，全部命中 L2，不读源文件（以调度器的读取计数为证）。
  3. 改单双页和排序，`shutdown` 后重建，书记忆恢复。
  4. 嵌套压缩包和 `.tar.gz` 书能打开和翻页。
  5. 外部改写 `settings.json`，运行中的会话收到变化并重新解析设置。
- App 接入：`-MVMockServices YES` 时仍用 Mock，否则用 `make`。

## 验收

- `make test` 通过，零警告，五个集成测试全部通过。
- `make` 的启动用时和 `shutdown` 的用时写在测试的断言里（≤ 200 ms、≤ 1 秒）。
- 辅助进程有调用卡住时（用 S1-T1 的故障方法），`shutdown` 仍在 1 秒内返回。
