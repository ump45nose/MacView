# S0-T4 契约代码与 Mock

前置：S0-T1。状态见 [roadmap](../roadmap.md)。

## 目标

把 [architecture.md](../../architecture.md) §4 的契约落成代码，并提供能跑通的 Mock，使前端在内核实现之前就能开发和测试。

## 范围

- 公开类型与协议：
  - 按 §4 的签名实现各模块的公开类型与协议。
  - 测试值类型的编解码与基本行为，例如：Location 的 JSON 往返、ContentIdentity 缓存键的稳定性、BookSettings 的逐字段合并。
- 契约中的具体类型，提供能跑通 Mock 的最小实现：
  - ReaderSession：打开书、单页导航、读取设置；页帧暂时一页一帧。
  - CommandRegistry：登记、启用判断、执行。
  - 双页拼合、预取计划、书记忆持久化和按键序列解析，留给 S1-T6、S1-T7。
- MVTestSupport 中的 Mock：
  - MockSourceRegistry：内存目录树；卷健康状态可以按脚本变化（healthy → degraded → unavailable）。
  - MockImagePipeline：
    - 生成带编号的合成图，依次交付占位图、浏览图、精确图。
    - 延迟和吞吐可以配置，默认模拟 NAS（2.5 张/秒）。
    - 可以注入超时、卷不可用等错误。
  - MockSettingsStore、MockBookLoader、MockBookshelf。
  - `CoreServices.makeMock(_:)`。

## 不做

- 任何真实的 I/O、解码和缓存。
- App 侧的接入（S1-F1）。

## 参考

- architecture.md §3（语义）、§4（签名）。

## 验收

- `make build test` 通过，零警告。
- 有一个测试用 `CoreServices.makeMock` 打开一本 100 页的模拟书，翻到第 50 页，并依次收到第 50 页的占位图、浏览图和精确图。
- 报告列出与 §4 的全部差异及原因，在 G0 时并入 §4。
